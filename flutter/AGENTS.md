# Flutter app (flixur client)

## Toolchain - Nix only

- Flutter is **pinned via the nix flake** (`flake.lock` → nixpkgs-unstable). Never use a
  system/global `flutter`. Our Dart is newer than most training data - don't assume
  version numbers, check with `tools/flutter-wrapped --version`.
  You might already be in the devshell. Check `flutter --version` first to make sure its >=3.13.3 and only use the wrapper if its not.
- Run **all** flutter commands through the wrapper (it sets the pkg-config/NIX\_\* flags
  needed for the Linux desktop build):
  ```
  tools/flutter-wrapped pub get
  tools/flutter-wrapped run -d linux
  tools/flutter-wrapped test
  tools/flutter-wrapped analyze
  ```
- Formatting goes through treefmt at repo root: `nix fmt`.
- Auto-fixes: `nix run .#dart-fix` (runs `pub get` + `dart fix --apply`).
- All dart/dart-tools commands must be run from this (`flutter/`) directory.
- Full treecodegen (openapi client, slang, themes, hive): `just generate` from repo root.
  Do NOT run bare `build_runner`/`dart run build_runner` - the nix wrapper mirrors the
  SDK layout because dart codegen can't resolve `dart:ui` under nix otherwise.

## Dart 3.13 language style - primary constructors

The SDK constraint is `sdk: 3.13.3`. **Prefer primary constructors** for new code, and
migrate nearby code you touch. Example, before → after:

```dart
// OLD (pre-3.13)
class Foo extends Bar {
  const Foo(this.x, {super.key});
  final int x;
}

// NEW (3.13 primary constructors)
class const Foo(int x, {super.key}) extends Bar;
```

Rules of thumb:

- `final`/`var` in the header = **declaring parameter**: it declares the field too
  (`class const Point(double x, double y);` gives you `final double x, y;`).
- Keep `const` in the header for const-constructible classes
  (`class const MainApp({super.key}) extends StatelessWidget` - see `lib/main.dart`).
- Constructor body goes in a `this { ... }` block:
  ```dart
  class const Counter(int start) {
    this { assert(start >= 0); }
  }
  ```
- Secondary **named constructors** use the shorthand - don't repeat the class name:
  ```dart
  class const Counter(int start) {
    new zero() : this(0);
  }
  ```
- Do NOT put `final`/`var` on regular function/method parameters - 3.13 reserves those
  modifiers for declaring parameters only (compile error otherwise).

Other recent language features to prefer:

- **Dot shorthands** (3.10+): when the context implies the type, use `.member` instead of
  the qualifier - `crossAxisAlignment: .stretch`, `Color c = .red;` (used heavily in this codebase).
- **Null-aware elements** (3.8): `[?maybeValue, ...]` in collections instead of manual null filtering.
- **Digit separators** (3.6): `1_000_000`.

## material_ui (official, split from the SDK)

- Since Flutter 3.47, Material and Cupertino are **standalone pub packages** published by
  flutter.dev, versioned independently of the SDK. The in-SDK `package:flutter/material.dart`
  is deprecated.
- **Always** import `package:material_ui/material_ui.dart` - never `package:flutter/material.dart`.
  The cupertino UI elements are NOT used in this project.

## Project layout / generated code

- `lib/gen/` - generated, never hand-edit.
- `openapi/` - dart-dio API client generated from the Go server's OpenAPI spec by
  `just generate`. Never hand-edit; it also carries its own analysis_options.
- `*.g.dart`, `*.freezed.dart` etc. - generated by build_runner; never hand-edit.
- `pubspec.lock.json` is derived from `pubspec.lock` (kept in sync by `just generate`) -
  regenerate it, don't hand-edit.
- Platform dirs (`android/`, `ios/`, `linux/`, `macos/`, `web/`, `windows/`) are excluded
  from analysis; only touch them for real platform-level changes.

## Lints / style

- `very_good_analysis` + repo overrides: **double quotes required**, no public API docs needed.
- Run `dart fix --apply` (via `nix run .#dart-fix`) before finishing changes; keep `analyze` clean.
- The app uses `flutter_hooks` - prefer `HookWidget` / hook-based state over raw
  `StatefulWidget` for new widgets where it fits.
